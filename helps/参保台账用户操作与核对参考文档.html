参保台账用户操作与核对参考文档

更新时间：2026-07-05

这份文档给业务用户使用，按当前系统最新功能整理。所有导入文件目前只支持 .csv，系统会自动识别 UTF-8、GBK/GB18030 编码。导入和导出等耗时操作都会进入任务中心，提交后请先查看任务中心结果，再回到页面核对数据。

一、先记住六个原则

  1. 先维护年度配置，再导入人员名单。
  2. 附件3《资助参保对象全量明细》是每月全量主名单，必须先导入附件3，附件4/5/6 和附件3人工调整回导才有对象可匹配。
  3. 附件1、附件2、附件7属于年度配置；附件3、附件4、附件5、附件6属于按月业务数据。
  4. 管理员负责配置、导入、导出、下放复核、收回复核和缴费金额核查确认。
  5. 镇街账号只处理已下放给本镇街且未收回的数据，主要填报是否参保、未参保原因、居民缴费金额、死亡时间和备注。
  6. 最终数据核对以 参保台账明细、参保导入记录、下放批次 和导出文件为准。

三、第一步：维护年度配置

入口：参保台账 -> 参保配置

选择年份后，依次维护五类配置。配置可手工新增、编辑、删除，也可按模板导入 CSV；新年度配置与旧年度相近时，可使用年度克隆。

1. 资助参保身份

来源：附件1《资助参保身份优先级配置》

作用：

  • 根据附件3身份判断 资助参保身份。
  • 根据 资助参保身份 + 居民医保缴费金额 + 资助金额 计算 参保类别。
  • 生成 资助参保对象-汇总名单 的动态身份勾选列。

需要重点核对：

配置列核对方式
优先级数字越小越优先
资助参保身份名称要与业务口径一致
资助档次/参保档次后续作为参保类别输出
资助标准与政策口径一致
个人实缴金额要能对应附件4或镇街填报缴费金额
资助代缴金额要能对应附件5代缴金额
包含参保身份有别名、细分类或历史名称时补充

2. 医疗救助身份

来源：附件2《医疗救助身份优先级配置》

作用：

  • 根据附件3身份判断 医疗救助身份。
  • 判断人员身份是否发生变更。

需要重点核对：

配置列核对方式
优先级/排序数字越小越优先
医疗救助身份名称要准确
包含参保身份一个大类包含多个明细身份时必须填写

3. 身份对应明细

来源：附件7《身份对应明细配置》

作用：

  • 根据 获得资助身份类别 + 居民医保缴费金额 判断 是否符合资助。

需要重点核对：

配置列核对方式
特殊人员身份后续匹配附件5的获得资助身份类别
实缴金额后续匹配居民医保缴费金额
包含参保身份有别名时补充，避免误判不符合资助

4. 未参保原因

入口：参保配置 -> 未参保原因

作用：

  • 镇街填报 是否参保=否 时，从配置项中选择未参保原因。
  • 默认常用原因包括死亡、服刑、服役、拒参、失踪、无法联系、已注销户口、户口迁出、其他。

核对重点：

  1. 原因名称要符合业务统计口径。
  2. 不再使用的原因可停用或删除。
  3. 镇街填报前先确认原因是否齐全。

5. 居民缴费金额

入口：参保配置 -> 居民缴费金额

作用：

  • 镇街填报居民缴费金额时，只能选择配置内金额。
  • 系统用镇街填报金额与附件4金额比对，生成缴费金额核查状态。

核对重点：

  1. 金额要和当年居民医保缴费标准一致。
  2. 如果镇街填报提示金额不在配置项中，先回到这里补充。

6. 年度克隆

入口：参保配置 -> 克隆年度

建议操作：

  1. 选择来源年份。
  2. 选择目标年份。
  3. 勾选要克隆的配置类型：资助参保身份、医疗救助身份、身份对应明细。
  4. 目标年份已有旧配置且需要重来时，才勾选覆盖。
  5. 克隆完成后抽查金额、优先级和包含身份。

四、第二步：导入附件3全量明细

入口：参保台账 -> 参保台账明细 -> 导入 -> 导入附件3全量明细

操作：

  1. 选择年份。
  2. 选择导入月份，例如 2026-03。
  3. 上传附件3 CSV。
  4. 提交后到任务中心查看是否成功。
  5. 再到 参保导入记录 查看总行数、成功行数、失败原因和未匹配身份。

附件3会写入：

字段来源或计算方式
姓名、身份证号码附件3对应字段
镇（街）、村（居）附件3对应字段
纳入资助时间附件3纳入资助时间；为空时使用导入月份
缴费时间附件3缴费时间
原始身份附件3医疗救助身份、特殊人员身份、身份类别等字段
医疗救助身份记录按附件2配置匹配并保留全部命中身份
医疗救助身份医疗救助身份记录中优先级最高的一项
资助参保身份记录按附件1配置匹配并保留全部命中身份
资助参保身份资助参保身份记录中优先级最高的一项
最后附件3月份本次导入月份

新增、变更、取消怎么判断

情况结果
本年度从未出现过这个身份证新增
本年度已有这个身份证，医疗救助身份变了变更
之前已经取消，本月又重新出现在附件3变更
本年度已有这个身份证，本月附件3没有这个人取消，并写入身份取消时间
本月重复导入且身份没变保持原来的新增、变更或取消状态

同一个身份证在附件3有多行时，系统会合并身份记录，取优先级最高的医疗救助身份和资助参保身份。

核对重点：

  1. 附件3如果存在身份证为空或身份为空的错误行，系统会停止导入，避免误判取消人员。
  2. 导入后看统计卡片中的总数、新增、变更、取消数量。
  3. 抽查多身份人员，确认优先级最高身份是否正确。
  4. 参保导入记录 中如出现优先级 9999 或未匹配身份，要回到配置中补身份或补包含参保身份，再重新导入附件3。

五、第三步：导入附件4参保核实

入口：参保台账明细 -> 导入 -> 导入附件4参保核实

前提：当前年份必须已经导入附件3。

附件4会写入：

字段来源
居民医保缴费金额附件4个人缴费金额或居民医保缴费金额
资助地或参保地（区外备注）居民医保所属区划、职工医保所属区划不是江津时写入
最后附件4月份本次导入月份

导入后会重新计算：

  • 参保类别
  • 是否参保
  • 未参保原因
  • 是否符合资助
  • 是否获得资助
  • 资助方式

如果该人员已经有镇街填报内容，附件4导入后还会结合镇街填报金额重新计算缴费金额核查状态。

核对重点：

  1. 随机抽查居民医保缴费金额是否与附件4一致。
  2. 区外参保人员是否出现区外备注。
  3. 如果整份文件失败，通常是年份、月份或身份证号码与当年附件3台账匹配不上。

六、第四步：导入附件5税务请款

入口：参保台账明细 -> 导入 -> 导入附件5税务请款

前提：当前年份必须已经导入附件3。

附件5会写入：

字段来源
资助金额附件5代缴金额或资助金额
获得资助身份类别附件5代缴类别、特殊人员身份类别或身份类别
税务请款批次附件5请款批次
税务第一批请款请款批次包含“第一”时，写入对应代缴金额
最后附件5月份本次导入月份

同一个身份证在附件5有多行时，资助金额会累加；第一批请款金额也会按第一批记录累加。

导入后会重新计算：

字段计算规则
参保类别资助参保身份 + 居民医保缴费金额 + 资助金额，匹配附件1配置
是否参保参保类别是居民一档、居民二档、大学生一档、大学生二档、需核实时为“是”
未参保原因是否参保为“是”时写“无”
是否符合资助纳入资助月份和缴费月份一致，并且附件7命中时为“是”
是否获得资助符合资助且资助金额大于 0 时为“是”
资助方式获得资助为“是”时为“系统资助”，否则为“事后资助”

核对重点：

  1. 资助金额是否与税务请款明细一致。
  2. 多行同身份证资助金额是否累加。
  3. 参保类别为 需核实 的人员，要检查附件1金额组合和身份是否能匹配。
  4. 是否符合资助为 否 的人员，要检查缴费时间、纳入资助时间和附件7身份对应明细。

七、第五步：导入附件6死亡名单

入口：参保台账明细 -> 导入 -> 导入附件6死亡名单

前提：当前年份必须已经导入附件3。

附件6会写入：

字段来源或结果
备注（卫健委死亡时间）附件6死亡时间
未参保原因死亡
是否参保否
参保类别清空
是否符合资助否
是否获得资助否
资助方式清空
最后附件6月份本次导入月份

核对重点：

  1. 有死亡时间的人员，列表死亡备注应有值。
  2. 死亡人员是否参保、是否符合资助、是否获得资助应按上表更新。
  3. 如果整份文件失败，通常是身份证号码没有匹配到当年台账。

八、第六步：附件3人工调整回导

入口：参保台账明细 -> 导入 -> 导入附件3人工调整回导

用途：当导出后经过人工核对，需要回写部分人工调整字段时使用。

前提：当前年份必须已经存在对应身份证的参保台账记录。

回导可更新字段：

字段说明
缴费时间支持缴费时间、缴费日期等表头
未参保原因人工核对后的未参保原因
资助地或参保地（区外备注）人工核对后的区外备注
备注（卫健委死亡时间）人工核对后的死亡备注
人工备注管理员人工备注

核对重点：

  1. 文件必须包含身份证号码或身份证号。
  2. 只回写文件里存在的可更新列，不存在的列不会覆盖原字段。
  3. 如果没有匹配到任何记录，检查年份和身份证号码。

九、第七步：镇街复核下放

入口：参保台账明细 -> 下放复核

管理员可按镇街、勾选记录或当前筛选条件下放给镇街填报核实。

下放方式：

下放方式适用场景
按镇街下放常规按镇街批量核实
勾选记录下放只下放少量指定人员
按筛选条件下放例如只下放需核实、待核查或某类身份人员

下放后：

  • 生成一条下放批次。
  • 对应明细写入当前下放批次。
  • 复核状态变为 待填报。
  • 镇街填报状态变为 未填报。
  • 已处于下放中的记录不会被重复下放。

核对重点：

  1. 下放前先确认年份、月份和筛选条件。
  2. 下放后到 下放批次 查看批次号、镇街、总数、待填报数、已填报数。
  3. 如果提示没有可下放记录，通常是记录已在下放中或筛选条件没有匹配到数据。

下放批次和明细

入口：参保台账明细 -> 下放批次

管理员可查看：

  • 批次号
  • 年份、月份
  • 下放镇街
  • 下放方式
  • 总数、待填报数、已填报数、已收回数
  • 批次状态：已下放、部分收回、已收回
  • 批次明细及每条记录当前填报状态

十、第八步：镇街填报

镇街账号入口：参保台账 -> 参保台账明细

镇街账号只能看到本镇街且复核状态为 待填报、已填报 的记录。已收回、未下放、其他镇街数据不可见。

镇街可填报字段：

字段填报要求
是否参保只能填 是、否 或留空
未参保原因是否参保为否时填写，从配置项中选择
居民医保缴费金额是否参保为是时填写，从配置金额中选择
死亡时间有死亡情况时填写
镇街备注填写核实说明

保存后：

  • 镇街填报状态变为 已填报。
  • 复核状态变为 已填报。
  • 写入填报人、填报时间。
  • 系统根据镇街填报内容重新计算参保类别、是否参保、未参保原因、是否符合资助、是否获得资助、资助方式和缴费金额核查状态。

镇街填报计算规则：

镇街填报情况系统结果
是否参保 = 否是否参保为否，使用镇街未参保原因，是否符合资助和是否获得资助为否
是否参保 = 是，但未填缴费金额参保类别为需核实，是否参保和资助相关结果为待核实，缴费金额待核查
填报缴费金额与附件4金额一致缴费金额核查状态为一致，并按该金额重新计算参保类别
填报缴费金额与附件4金额不一致缴费金额核查状态为待核查，参保类别为需核实
附件4金额为空但镇街填了金额缴费金额核查状态为待核查

核对重点：

  1. 镇街填报金额必须先维护在 居民缴费金额 配置中。
  2. 镇街填报 否 时要选择合理未参保原因。
  3. 镇街保存后，管理员应关注 待核查 数据。

十一、第九步：收回复核

入口：参保台账明细 -> 收回复核

管理员可按批次或勾选记录收回复核权限。

收回后：

收回对象结果
整个批次批次状态变为已收回，明细状态变为已收回
部分记录相关明细状态变为已收回，批次可能变为部分收回
参保台账明细当前下放批次清空，复核状态变为已收回

核对重点：

  1. 收回后镇街账号不再看到这些记录。
  2. 已收回记录如果需要再次给镇街处理，可重新下放。
  3. 收回前建议先导出或记录镇街已填报信息。

十二、第十步：缴费金额核查确认

入口：参保台账明细 -> 缴费金额核查

管理员针对 缴费金额核查状态=待核查 的记录进行确认。

待核查常见原因：

原因说明
附件4缴费金额为空镇街填了金额，但系统来源金额为空
镇街金额与附件4金额不一致系统会记录两边金额差异
镇街填报参保但缴费金额为空需要补充或人工确认

确认后：

  • 缴费金额核查状态变为 已核查。
  • 可保存核查备注。

核对重点：

  1. 确认前对照附件4、镇街填报记录和实际缴费凭证。
  2. 备注中写清核查依据，便于后续追溯。

十三、第十一步：导出

入口：参保台账明细 -> 导出

导出后到任务中心下载。镇街账号导出时，系统自动限制为本镇街已下放未收回可见数据。

导出文件建议导出时机主要核对
资助参保对象-汇总名单导入附件1、附件2、附件3后动态身份列是否按资助参保身份记录打勾
资助参保对象-对比结果导入附件3后新增、变更、取消是否正确
特殊对象资助参保台账附件3、4、5、6、镇街复核和人工回导完成后金额、参保类别、是否符合资助、死亡备注、人工备注是否完整

导出口径：

文件当前范围
汇总名单当前筛选条件下的台账数据，身份列随当年资助参保身份配置动态生成
对比结果当前筛选条件下新增、变更、取消数据
特殊对象资助参保台账当前筛选条件下完整台账字段

十四、常见问题核对

1. 为什么有人是“需核实”

通常原因：

  1. 附件4个人缴费金额没导入或没匹配上。
  2. 附件5资助金额没导入或没匹配上。
  3. 附件1资助参保身份配置里没有对应身份和金额组合。
  4. 身份名称不一致，需要补 包含参保身份。
  5. 镇街填报缴费金额与附件4金额不一致。

2. 为什么是否符合资助是“待核实”

通常原因：

  1. 缴费时间为空。
  2. 纳入资助时间或缴费时间格式不规范。
  3. 镇街已填报参保但缴费金额为空。
  4. 缴费金额处于待核查状态。

3. 为什么是否符合资助是“否”

通常原因：

  1. 纳入资助月份和缴费月份不是同一个月。
  2. 附件7身份对应明细没有匹配到 获得资助身份类别 + 居民医保缴费金额。
  3. 身份别名未配置，需要补 包含参保身份。
  4. 附件6死亡名单或镇街填报未参保导致结果更新为否。

4. 为什么导入附件4/5/6失败

通常原因：

  1. 还没有先导入附件3。
  2. 选择的年份不对。
  3. 导入月份选择不对。
  4. 文件里的身份证号码和当前年度台账无法匹配。
  5. 文件表头不是系统模板要求的表头。

5. 为什么身份优先级是 9999

表示附件3里的身份没有匹配到当前年度配置。

处理方式：

  1. 回到参保配置。
  2. 检查资助参保身份或医疗救助身份是否缺失。
  3. 如果是别名、细分类或历史名称，编辑配置并补到 包含参保身份。
  4. 重新导入附件3。

6. 为什么镇街账号看不到数据

通常原因：

  1. 管理员还没有下放复核。
  2. 数据已经被管理员收回。
  3. 镇街账号没有绑定镇街。
  4. 账号绑定镇街和台账镇街名称不一致。
  5. 年份、月份或筛选条件选错。

7. 为什么不能下放复核

通常原因：

  1. 没有选择镇街、记录或有效筛选条件。
  2. 当前筛选条件没有匹配到数据。
  3. 记录已经处于下放中，不能重复下放。
  4. 当前账号是镇街账号，不允许下放。

8. 为什么缴费金额待核查

通常原因：

  1. 镇街填报金额与附件4金额不一致。
  2. 附件4金额为空。
  3. 镇街填报参保但没有填缴费金额。

处理方式：

  1. 对照附件4、镇街填报和实际缴费凭证。
  2. 必要时让镇街修正填报。
  3. 管理员确认后标记为 已核查 并填写备注。

十五、推荐核对流程

  1. 配置页确认附件1、附件2、附件7、未参保原因、居民缴费金额都有当前年份数据。
  2. 导入附件3后，看统计卡片新增、变更、取消数量。
  3. 到参保导入记录查看是否有未匹配身份或失败原因。
  4. 抽查 5 到 10 个多身份人员，确认医疗救助身份和资助参保身份取最高优先级。
  5. 导入附件4后，核对居民医保缴费金额和区外备注。
  6. 导入附件5后，核对资助金额、参保类别、是否符合资助。
  7. 导入附件6后，核对死亡备注和死亡人员结果。
  8. 如有人工调整，导入附件3人工调整回导并抽查回写字段。
  9. 管理员按镇街、勾选记录或筛选条件下放复核。
  10. 镇街填报后，核对已填报数、未参保原因和缴费金额。
  11. 管理员处理缴费金额待核查记录。
  12. 必要时收回异常批次或异常记录，修正后重新下放。
  13. 导出对比结果，核对新增、变更、取消。
  14. 导出特殊对象资助参保台账，核对最终字段是否完整。

十六、镇街账号能做什么

镇街账号只能看和处理本镇街已下放、未收回的数据。

建议开放：

  • 参保台账明细查看
  • 本镇街可见数据导出
  • 是否参保、未参保原因、居民缴费金额、死亡时间、镇街备注填报

不建议开放：

  • 参保配置
  • 附件3/4/5/6 导入
  • 附件3人工调整回导
  • 参保导入记录
  • 下放复核和收回复核
  • 下放批次管理
  • 缴费金额核查确认

镇街账号进入页面后，系统会自动限制为本镇街数据，并且只显示复核状态为 待填报、已填报 的记录。
