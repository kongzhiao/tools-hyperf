数据核实用户操作与核对参考文档

更新时间：2026-07-23

本模块用于按年度导入参保原始数据，匹配参保档次、资助身份和认定区，处理待匹配或疑似记录，并生成税务和参保汇总结果。

三、参保数据管理页面

入口：数据核实 -> 参保数据管理

进入后先选择年度。可按姓名、身份证号、街道乡镇、代缴类别、档次、医疗救助类别及四类匹配状态查询。

统计卡展示总数、正确、待匹配、疑似和代缴金额；列表可查看人员、金额、日期及匹配状态。统计卡和列表都受当前筛选条件影响时，应以当前筛选范围为准核对。

四、年份管理

1. 创建年度

  1. 点击 年份管理，创建 2020—2030 范围内尚不存在的年度。
  2. 填写或编辑年度说明，并设置是否启用。
  3. 返回主页面选择新年度，再开始导入。

2. 清空或删除年度

不可逆操作：清空年度数据会删除所选年度全部参保数据；年份有数据时不能直接删除年份。清空前先导出留档，并再次核对年份和记录数。

五、导入原始数据

  1. 选择年度，点击 导入原始数据。
  2. 下载 数据核实-原始数据.csv，必填表头为：序号、姓名、身份证号、街道乡镇、代缴类别、代缴金额。
  3. 上传不超过 128MB 的 CSV，先执行文件校验。
  4. 选择导入方式：增量保留现有数据并新增；全量先删除所选年度全部数据再导入。
  5. 确认后到任务中心查看完成状态，再回到列表刷新。
自动匹配：原始导入时会按“年度 + 代缴类别 + 代缴金额”初步匹配档次。若配置缺失或存在多条可匹配配置，记录会进入待处理状态。

六、导入档次匹配数据

  1. 下载 数据核实-匹配档次数据.csv。
  2. 至少填写 身份证号 和 个人实缴金额。
  3. 选择正确年度，上传并通过校验后确认导入。
  4. 系统按身份证号找到该年度原记录，再按“年度 + 原记录代缴类别 + 个人实缴金额”匹配档次。
  5. 唯一匹配时更新档次；没有匹配或匹配到多条时标记为未匹配。

七、匹配身份和认定区

  1. 下载 数据核实-匹配身份和认定区数据.csv。
  2. 填写身份证号、认定区和资助身份。
  3. 上传并通过校验后确认，任务完成后刷新列表。
  4. 资助身份会通过类别转换配置转换为税务标准口径。
  5. 认定区为 江津区 时认定区匹配为正确；为空或其他值会进入疑似核对。

完成后系统会综合档次、医疗救助身份和认定区结果重新计算总体匹配状态。

八、处理待匹配和疑似数据

1. 逐条编辑

点击行内编辑，可核对姓名、身份证号、街道乡镇、代缴类别及金额、档次、个人实缴、医疗救助类别、付款日期、备注和各类状态。金额不得为负数。

2. 批量更新

勾选多条记录后使用批量更新，可统一修改档次、个人实缴金额、医疗救助类别、付款日期、备注及匹配状态。只填写本次确需更新的字段，保存前再次核对选中数量。

不要用状态掩盖数据问题：先修正类别、金额或认定区等业务值，再调整状态。批量把记录直接改为“正确”会造成汇总口径失真。

九、导出和任务中心

导出匹配结果按当前年度及筛选条件提交异步任务。提交后打开任务中心，等待状态从“待执行/执行中”变为“已完成”，再点击下载。任务生成的文件下载有效期为 7 天，应及时归档。

十、税务汇总

入口：数据核实 -> 税务汇总

选择年度后查看各代缴类别的人数和代缴金额及合计。先核对正确、待匹配和疑似数量，再导出 Excel；如果仍有待匹配或疑似，汇总只能作为阶段性结果。

十一、参保汇总

入口：数据核实 -> 参保汇总

选择年度后，系统按街道乡镇以及类别、档次动态汇总人数和金额。导出前重点核对镇街合计、类别档次小计和总计是否与参保数据管理筛选结果一致。

十二、最终核对清单

  • 年度正确，业务配置已经完成并经过抽查。
  • 原始数据导入数量与来源文件一致。
  • 同一身份证号没有因重复导入形成异常记录。
  • 待匹配和疑似记录已逐项说明或处理。
  • 抽查人员的类别、档次、个人实缴和代缴金额一致。
  • 税务汇总、参保汇总与明细筛选合计一致。
  • 导出文件已从任务中心下载并按年度归档。

十三、常见问题

现象核对方法
下拉中没有目标年度先在年份管理创建并启用年度。
档次一直未匹配核对年度、代缴类别、代缴金额或个人实缴金额是否存在唯一配置。
资助身份无法转换到类别转换配置核对来源名称及目标税务口径。
认定区显示疑似核对来源值是否准确为“江津区”。
导入后原数据消失可能选择了全量导入；从留档文件恢复并重新导入。
导出后找不到文件到任务中心查看状态；已完成且未过期时点击下载。
本文档按当前系统页面、操作按钮和业务规则整理。实际可见菜单及按钮以当前账号已分配范围为准。
