# 文档规范

## 基本要求

- 默认简体中文，代码符号和字段保留原文。
- 只描述当前可从代码、路由和迁移验证的事实。
- 规划、建议、已知限制必须明确标识，不能伪装为已实现。
- 不记录真实密码哈希、Token、身份证、银行账号、环境口令和生产数据。

## 公共文档

公共规则放在 `docs/share/`：项目概览、开发规范、接口规范、文档规范。功能独有内容不得堆入公共规范。

## 功能目录

```text
docs/功能名称/
├── README.md
├── 用户说明.md
├── 业务流程图解.md
├── 业务数据模型.md
└── 业务变更增量.md
```

### README

包含目标、角色、业务边界、入口、接口、权限、依赖、已实现事实和限制。

### 用户说明

包含使用前提、逐步操作、核对点、角色差异和常见错误。两个台账可参考 `helps/` 最新 HTML，但冲突时以代码为准。

### 业务流程图解

包含总流程、核心计算、状态机、异常分支和范围校验，使用 Mermaid 时节点文字加引号以避免解析歧义。

### 业务数据模型

每张业务表至少记录：

- 表用途与软删除/时间戳策略。
- 每个字段的类型、长度或精度、可空、默认、边界和注释。
- 主键、普通索引、唯一约束和逻辑关联。
- JSON/枚举字段的结构和值域。
- 迁移追加字段后的最终形态。

普通索引不能写成唯一约束；只由应用层保证的匹配键需明确标注。

### 业务变更增量

按日期倒序追加新增、调整、限制和待确认项。不重写历史。本次首次整理记为 2026-07-12“现状基线建立”。

## 来源引用

- 路由：`config/routes.php`。
- 数据结构：根 `migrations/` 与实际模型；SQL 快照仅辅助确认存量表。
- 业务规则：Service、Controller、Job。
- 用户操作：前端页面与 `helps/`。

## 同步

- 接口、字段、状态、权限、CSV表头或流程变化时，同步前后端文档。
- 用户操作变化时评估是否更新 `helps/`，没有授权则只记录待同步。
- 文档完成后运行 `codegraph sync`。
