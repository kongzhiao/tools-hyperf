# 未救助台账业务数据模型

金额统一 `decimal(14,2)`，默认 `0`；主业务表使用 `created_at`、`updated_at`，未救助、应补应退、通知、重大疾病和筛查表按迁移说明使用软删除。兼容性原因数据库表仍使用 `wash` 命名。

## unrescued_wash_configs

| 字段 | 类型 | 空/默认 | 注释/索引 |
|---|---|---|---|
| `id` | bigint | 自增 | PRIMARY |
| `version` | varchar(50) | 空串 | 规则版本；索引 |
| `name` | varchar(100) | 空串 | 配置名 |
| `rule_name` | varchar(100) | 空串 | 兼容旧字段 |
| `data` | json | 可空 | 规则数组 |
| `is_active` | tinyint | 1 | 是否启用；与created_at组合索引 |
| `created_by` | bigint | 0 | 创建用户ID |
| 时间戳+`deleted_at` | timestamp | 可空 | 软删除 |

`data` 中 `outpatient_major_disease` 必须位于规范化规则的第一项，字段如下：

| 字段 | 类型/边界 | 默认值 | 说明 |
|---|---|---|---|
| `code` | string/固定值 | `outpatient_major_disease` | 规则唯一编码 |
| `enabled` | boolean | `true` | 仅启用时匹配 |
| `action` | `keep`或`exclude` | `keep` | 命中后保留或剔除 |
| `medical_categories` | string[]/至少一项 | `门诊慢特病`,`造口袋门诊` | 医疗类别精确匹配集合 |
| `disease_codes` | string[]/可空 | `M00500` | 用户指定编码，去空格并转大写后精确匹配 |
| `operator` | string/固定值 | `compound` | 表示复合条件，由专用逻辑执行 |
| `remark` | string/最长受主表255限制 | 门诊重大疾病匹配，标记为拟通知2 | 命中备注 |

重大疾病编码库只读取 `unrescued_disease_configs.status=1` 且未软删除的记录。未救助和应补应退配置通过不同 `rule_name` 隔离，当前兼容值分别为“未救助默认清洗规则”和“应补应退清洗规则”。

## unrescued_supplement_records

该表和模型仍存在，保存另一类补充排查记录，但当前三个主要页面和公开主流程不以它作为核心节点。字段包括周期/批次、人员身份/镇街、参保就医、10类金额、`calc_medical_assistance_amount`、状态、备注和软删除时间；主要索引为 period+id_card、period+town、period+status、disease_code。新增业务不得误把它与当前 `unrescued_refund_records` 合并，使用前需确认实际调用链。

## 关联与安全

- 各表 `town_id` 逻辑关联 `towns.id`，未声明外键。
- `created_by` 逻辑关联 `users.id`，未声明外键。
- 动态医疗类别、身份和筛查规则选项写入共享 `business_filter_options`；其字段为 `id`、`module varchar(100)`、`type varchar(100)`、`value varchar(255)`、`label varchar(255)`、`status tinyint`、`sort int`、`source_batch varchar(50)`、`remark varchar(255)`、时间戳和软删除。索引为 `(module,type,value)` 与 `(module,type,status)`，均非唯一。
- 清算期、序号和身份证匹配主要由应用层保证；并发重复风险需要后续单独评估唯一约束。
