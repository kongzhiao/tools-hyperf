# 未救助台账用户说明

本说明是后端业务文档，面向业务用户的完整离线页面位于 `helps/未救助台账用户操作与核对参考文档.html`（更新于2026-07-12）。

## 管理员流程

1. 维护镇街、用户镇街绑定和重大疾病编码。
2. 未救助明细选择清算期，先导入附件1，再导入附件2。
3. 检查匹配状态、金额和状态分档，配置并执行未救助明细筛查。
4. 导出未剔除排查明细，交线下核对。
5. 应补应退选择清算期，先导入附件4，再独立导入附件2。
6. 单独配置并执行应补应退筛查，重点检查重大疾病优先保留、正负抵消和已享受救助。
7. 导出排查结果。
8. 把最终需通知数据导入下放通知，按镇街下放。
9. 核对镇街反馈和实际拨付后填写管理员备注、标记报销并导出归档。

两个台账的筛查配置相互独立。系统先按进入报销金额确定基础状态，仅金额大于300元的记录参与首项重大疾病匹配；命中后默认保留并跳过后续规则，也可在当前台账配置为剔除，金额状态不会被该规则覆盖。

所有导入、筛查和导出提交后必须在任务中心核验最终结果。

## 镇街流程

1. 使用绑定正确镇街的账号进入下放通知。
2. 对已下放未接收数据确认接收。
3. 线下通知群众后标记已通知，错误标记可撤销。
4. 回填联系人、联系电话、开户行、户名、银行账号和镇街备注。
5. 仅导出本镇街可见通知明细。

镇街账号不能维护重大疾病、导入/筛查排查明细、下放、填写管理员备注或标记报销。

## 核对重点

- 附件1/4有效行数与任务结果接近。
- 进入报销金额按对应公式正确。
- 金额小于等于0、0至300元、大于300元分别对应无救助金额、拟通知1、拟通知2；前两档不得命中重大疾病首项。
- 附件2按身份证更新同清算期全部记录。
- 未匹配镇街的数据不能进入下放。
- 已接收/已通知不能撤销下放。
- 已报销必须对应真实拨付或报销结果。
- 导出范围受当前筛选、剔除状态和镇街范围影响。
