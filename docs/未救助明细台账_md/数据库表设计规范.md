# 未救助明细台账 - 数据库设计文档

按照 AI 开发规范，所有表统一使用 `InnoDB` 引擎，字符集 `utf8mb4_unicode_ci`，均包含完整的 `id` (bigint unsigned) 以及 `created_at`, `updated_at`, `deleted_at` 字段。所有其他字段的类型设定均遵循规范要求，默认值设置合理，避免空异常。

---

## 1. 未救助明细表 (`unrescued_records`)

**说明**：核心主数据表，存储从附件1导入的基础流水，通过附件2缝合的归属地和身份，以及最终镇街人员填报的财务账户信息。

| 字段名 | 数据类型 | 可空 | 默认值 | 字段说明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | bigint UNSIGNED | 否 | AUTO_INCREMENT | 主键 |
| `sequence_no` | varchar(50) | 否 | '' | 序号 (附件1唯一匹配键) |
| `name` | varchar(50) | 是 | NULL | 姓名 |
| `id_card` | varchar(18) | 是 | NULL | 身份证号 (附件2关联键) |
| `medical_category` | varchar(100) | 是 | NULL | 医疗类别 |
| `disease_code` | varchar(50) | 是 | NULL | 病种编码 |
| `disease_name` | varchar(255) | 是 | NULL | 病种名称 |
| `cert_location` | varchar(100) | 是 | NULL | 认定地 |
| `hospital_name` | varchar(255) | 是 | NULL | 医药机构名称 |
| `hospital_code` | varchar(100) | 是 | NULL | 医药机构编码 |
| `in_out_city` | varchar(50) | 是 | NULL | 市（内）外 |
| `admission_date` | date | 是 | NULL | 入院时间 |
| `discharge_date` | date | 是 | NULL | 出院时间 |
| `settlement_time` | datetime | 是 | NULL | 结算时间 |
| `total_fee` | decimal(14,2) | 否 | 0.00 | 医疗总费用 |
| `policy_fee` | decimal(14,2) | 否 | 0.00 | 医保政策范围费用 |
| `pool_fund_pay` | decimal(14,2) | 否 | 0.00 | 统筹报销金额 |
| `large_amount_pay` | decimal(14,2) | 否 | 0.00 | 大额报销 |
| `serious_illness_pay` | decimal(14,2) | 否 | 0.00 | 大病报销 |
| `used_outpatient_rescue` | decimal(14,2) | 否 | 0.00 | 已使用门诊救助金额 |
| `used_normal_rescue` | decimal(14,2) | 否 | 0.00 | 已使用普通住院救助金额 |
| `used_major_rescue` | decimal(14,2) | 否 | 0.00 | 已使用重特大疾病救助金额 |
| `used_large_fee_rescue` | decimal(14,2) | 否 | 0.00 | 已使用大额费用住院救助 |
| `calc_reimbursement_amount`| decimal(14,2) | 否 | 0.00 | 进入报销金额 (系统基于公式计算) |
| `settlement_period` | varchar(20) | 是 | NULL | 清算期 (如202601) |
| `street_town` | varchar(100) | 是 | NULL | 镇街 (来源附件2) |
| `village` | varchar(100) | 是 | NULL | 村社 (来源附件2) |
| `priority_identity` | varchar(100) | 是 | NULL | 优先身份/对象类别 (来源附件2) |
| `status` | varchar(50) | 否 | '待处理' | 状态(待处理、无救助金额、不通知、待通知、已下放、已接收、已通知) |
| `reimbursement_status` | varchar(20) | 否 | '未报销' | 报销状态 (未报销、已报销) |
| `exclude_status` | varchar(20) | 否 | '未剔除' | 剔除状态 (未剔除、已剔除) |
| `remark` | varchar(255) | 是 | NULL | 备注 (主要用于记录被剔除的原因) |
| `bank_name` | varchar(100) | 是 | NULL | 开户行 (镇街回填) |
| `bank_account_name` | varchar(100) | 是 | NULL | 户名 (镇街回填) |
| `bank_account_no` | varchar(100) | 是 | NULL | 账号录入 (镇街回填) |
| `created_at` | timestamp | 是 | NULL | 创建时间 |
| `updated_at` | timestamp | 是 | NULL | 更新时间 |
| `deleted_at` | timestamp | 是 | NULL | 软删除时间 |

**建议索引**：
- `UNIQUE INDEX idx_sequence_no` (`sequence_no`) - 防止导入数据重复。
- `INDEX idx_id_card` (`id_card`) - 方便附件2快速匹配。
- `INDEX idx_street_town_status` (`street_town`, `status`) - 优化镇街人员的检索与拉取速度。
- `INDEX idx_settlement_period` (`settlement_period`) - 按月份筛查的常用条件。

## 2. 清洗规则配置表 (`unrescued_wash_config`)

**说明**：用于存储系统数据清洗时的 JSON 规则，避免将规则写死在代码中。每次更新仅保存最新一条有效数据或追加版本。

| 字段名 | 数据类型 | 可空 | 默认值 | 字段说明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | bigint UNSIGNED | 否 | AUTO_INCREMENT | 主键 |
| `data` | json | 是 | NULL | 清洗规则的 JSON 数据 |
| `created_at` | timestamp | 是 | NULL | 创建时间 (配置保存时间) |
| `updated_at` | timestamp | 是 | NULL | 更新时间 |
| `deleted_at` | timestamp | 是 | NULL | 软删除时间 |

## 3. 救助重大疾病配置表 (`unrescued_disease_configs`)

**说明**：由导入附件3生成，用于维护重大疾病字典，供后续规则引擎匹配门诊慢特病时使用。

| 字段名 | 数据类型 | 可空 | 默认值 | 字段说明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | bigint UNSIGNED | 否 | AUTO_INCREMENT | 主键 |
| `disease_code` | varchar(50) | 否 | '' | 病种编码 (导入匹配唯一键) |
| `disease_name` | varchar(255) | 是 | NULL | 病种名称 |
| `created_at` | timestamp | 是 | NULL | 创建时间 |
| `updated_at` | timestamp | 是 | NULL | 更新时间 |
| `deleted_at` | timestamp | 是 | NULL | 软删除时间 |

**建议索引**：
- `UNIQUE INDEX idx_disease_code` (`disease_code`) - 保证病种编码全局唯一。
