# 未救助明细台账数据库表设计规范

> 本设计为新模块专用表设计，不复用既有业务主表。除用户、角色、权限底座外，未救助模块数据独立闭环。  
> 按项目规范：所有业务表使用 InnoDB、`utf8mb4_unicode_ci`；包含 `id`、`created_at`、`updated_at`、`deleted_at`；不使用外键、枚举、视图、触发器、存储过程。  
> 金额字段统一 decimal，服务端计算使用 BCMath 保留 2 位。

## 1. 表清单

| 表名 | 说明 |

## 2. `towns` 镇街组织表

用于维护镇街名称、编码和账号数据权限。当前旧平台 `users` 表无镇街字段，新模块建议给 `users` 增加 `town_id` 字段，或新增用户镇街关系表。为简化权限过滤，优先建议 `users.town_id`。

| 字段名 | 类型 | 可空 | 默认值 | 说明 |
| :--- | :--- | :---: | :--- | :--- |
| `id` | bigint unsigned | 否 | auto_increment | 主键 |
| `name` | varchar(100) | 否 | '' | 镇街名称 |
| `code` | varchar(50) | 否 | '' | 镇街编码，可为空字符串 |
| `status` | tinyint | 否 | 1 | 状态：1正常，0禁用 |
| `sort` | int | 否 | 0 | 排序 |
| `created_at` | timestamp | 是 | null | 创建时间 |
| `updated_at` | timestamp | 是 | null | 更新时间 |
| `deleted_at` | timestamp | 是 | null | 软删除时间 |

索引建议：

- `idx_name`：`name`
- `idx_status_sort`：`status, sort`

## 10. 数据口径说明

### 附件1主链路

- 附件1按 `settlement_period + sequence_no` 匹配更新。
- 附件2按 `settlement_period + id_card` 更新当月同人多条附件1记录。
- 附件2不单独落表；姓名只在附件1姓名为空或为 `--` 时补充到主表 `name`。
- `calc_reimbursement_amount` 不扣医疗救助金额和渝快保金额。

### 附件4应补应退链路

- 数据与附件1主链路独立。
- 附件4可以复用附件2导入后沉淀在主表中的对象信息和附件3重大疾病配置。
- 普通住院直接保留；门诊慢特病需病种编码命中 `unrescued_disease_configs`；其他医保就诊类别不纳入。
- 金额公式扣医疗救助金额和渝快保报销金额，无值按 0。

### 导出附件2未报销台账

- 数据范围为主表中排除 `exclude_status = 已剔除` 的记录。
- 不强制要求状态必须为已通知。
- 银行账户信息有则导出，无则保留为空。
