# 业务敏感数据加密上线说明

## 上线前准备

1. 完整备份生产数据库，并验证备份可以恢复。
2. 在 Git 仓库之外备份生产私钥，限制只有部署账号可读。
3. 部署代码和公钥；通过 `FIELD_PRIVATE_KEY_PATH` 注入生产私钥，设置权限为 `600`。
4. 如需让盲索引密钥与私钥解耦，配置长期固定的 `FIELD_INDEX_KEY`；首次上线后不得随意更换。
5. 安排维护窗口，暂停导入、编辑、批量更新和其他会写入目标表的任务。

## 升级步骤

```bash
php bin/hyperf.php migrate
php bin/hyperf.php data:encrypt-sensitive --dry-run
php bin/hyperf.php data:encrypt-sensitive --chunk=500 --verify
```

- `--dry-run` 只统计，不写数据，用于验证表、字段、密钥和加解密自检。
- 正式执行按主键分批提交，每张表在 Redis 保存检查点。
- 中断后使用 `php bin/hyperf.php data:encrypt-sensitive --chunk=500 --resume --verify` 继续。
- 可用 `--table=表名` 单独演练或处理某张表。
- 命令只输出表名和数量，不输出姓名、证件号、账户等数据。

## 查看实时进度

执行窗口会在每个批次完成后立即打印总进度和当前业务进度，例如：

```text
正在检查：统计明细｜总进度 72.35%｜当前业务进度 48.20%
```

同样的信息会写入独立日志：

```bash
tail -f runtime/logs/sensitive-encryption.log
```

如果命令通过 `docker exec` 执行，当前执行终端可以直接看到标准输出；这类输出通常不归入容器主进程的 `docker logs`。需要在另一个终端观察时，可执行：

```bash
docker exec tools-yf tail -f /opt/www/runtime/logs/sensitive-encryption.log
```

- 每次执行都有独立运行编号，可用于区分演练、正式升级和续跑。
- 日志只显示正在执行的业务、全部任务进度、当前业务进度以及最终结果。
- 正式执行每批事务提交后才更新 Redis 检查点并打印完成进度。
- `dry-run` 同样打印进度，但不写数据库，也不保存续跑检查点。
- 日志不记录任何业务字段值。

## 升级后验证

1. 抽查数据库：非空目标字段应为 `ENC1:` 开头的密文，相应盲索引应为 64 位摘要。
2. 验证列表和详情仍显示完整业务值。
3. 使用完整姓名、完整身份证件号等执行精确搜索。
4. 验证导入、编辑、批量更新、导出和统计流程。
5. 验证 `NULL` 和空字符串未被改成密文或互相转换。
6. 观察应用错误日志，确认没有密钥不可读、密文格式错误或字段长度不足。
7. 验证通过后恢复业务写入。

## 回退原则

- 已写入密文后，迁移代码会阻止直接把字段缩回旧长度或删除盲索引列。
- 如果必须回退，应先停止业务、恢复升级前的完整数据库备份和匹配的应用版本。
- 不要尝试在数据库中手工修改密文，也不要删除 `ENC1:` 前缀。

## 日常使用影响

- 业务页面仍显示完整值，操作方式不变。
- 搜索框必须输入完整值进行精确查询；原来的任意片段模糊搜索不再适用于加密字段。
- 加密使用随机数，同一明文多次保存的密文不同，这是正常现象；精确搜索依靠稳定盲索引完成。
