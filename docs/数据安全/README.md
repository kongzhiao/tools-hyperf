# 业务敏感数据加密

## 目标与范围

第一批只处理明确确认的业务关键字段：姓名、身份证件号、人员编号、结算编号、联系电话和银行账户相关字段。第二批日志、附件、临时文件等内容不在本次范围内，避免扩大改造面。

## 实现规则

- 采用项目已有 OpenSSL 能力，不新增第三方加密包。
- 每个非空值使用随机 AES-256-GCM 数据密钥加密，再使用现有 RSA 公钥封装数据密钥。
- 数据库存储值以 `ENC1:` 开头，用于区分密文和迁移期明文；该标识不表示每次保存都会升级版本，已加密值不会重复加密。
- `NULL` 继续保存为 `NULL`，空字符串继续保存为空字符串。
- 模型写入时自动加密，模型读取时自动解密；接口、列表和导出仍返回完整业务值，不额外脱敏。
- 需要查询的字段使用 HMAC-SHA256 盲索引，只支持完整值精确匹配，不支持 `LIKE` 片段查询。
- 迁移期查询同时兼容盲索引和旧明文；旧数据全部升级后由盲索引命中。
- 实际统计汇总表名称统一为现有数据库使用的 `statistics_summery`。

## 代码入口

- 密码服务：`app/Service/SensitiveDataCipher.php`
- 模型透明加解密：`app/Model/Concerns/HasEncryptedAttributes.php`
- 字段和索引迁移：`migrations/2026_08_23_100002_add_sensitive_field_encryption_columns.php`
- 老数据升级命令：`app/Command/EncryptSensitiveDataCommand.php`
- 配置：`config/autoload/security.php`
- 独立进度日志：`runtime/logs/sensitive-encryption.log`

命令每处理完一个批次会同时向终端和独立日志写入表名、累计扫描数、总数、百分比、本批变更数、累计变更数、最后主键和耗时。日志不包含姓名、证件号、银行账户、明文或密文内容；日志文件不可写时命令会停止，避免在没有审计记录的情况下继续升级。

## 密钥边界

- 默认公钥路径：`config/extends/global_publickey.pem`。
- 默认私钥路径：`config/extends/global_privatekey.key`；生产推荐通过 `FIELD_PRIVATE_KEY_PATH` 指向部署系统单独注入的私钥。
- 私钥文件权限必须为 `600` 或更严格；生产环境启动升级命令前会检查。
- 私钥不进入 Git 仓库，也不得出现在文档、日志、命令参数或构建产物中。
- 私钥丢失后现有密文无法恢复，生产上线前必须在仓库之外做受控备份。
- 可选配置 `FIELD_INDEX_KEY` 作为独立盲索引密钥；未配置时由私钥派生。

## 上线前提

生产数据库不能直接边运行边盲目升级。必须先完整备份数据库和私钥，在维护窗口执行表结构迁移、演练、分批升级及验证，具体见《用户说明》。
