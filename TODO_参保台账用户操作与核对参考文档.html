参保台账用户操作与核对参考文档

这份文档给业务用户使用，按步骤操作即可。所有导入文件目前只支持 .csv，系统会自动识别 UTF-8、GBK/GB18030 编码。

一、先记住三个原则

  1. 先做配置，再导入人员名单。
  2. 附件3是每月全量名单，必须先导入附件3，附件4/5/6才有对象可匹配。
  3. 最终数据核对以“参保台账明细”和导出文件为准。

二、第一步：维护年度配置

手动操作入口：参保台账 -> 参保配置

选择年份后，依次维护三类配置。

1. 资助参保身份

来源：附件1《资助参保身份优先级配置》

作用：

  • 用来判断“资助参保身份”。
  • 用来计算“参保类别”。
  • 用来生成“汇总名单”的动态身份勾选列。

核对重点需要重点核对：

配置列核对方式
优先级数字越小越优先
资助参保身份名称要与业务口径一致
资助/参保档次后面会生成参保类别
个人实缴金额要能对应附件4个人缴费金额
资助代缴金额要能对应附件5代缴金额
包含参保身份有别名时在页面新增/编辑里补充

2. 医疗救助身份

来源：附件2《医疗救助身份优先级配置》

作用：

  • 用来判断“医疗救助身份”。
  • 用来判断人员是新增、变更还是取消。

核对重点需要重点核对：

配置列核对方式
优先级数字越小越优先
医疗救助身份名称要准确
包含参保身份例如一个大类包含多个明细身份时，需要填写

3. 身份对应明细

来源：附件7《身份对应明细配置》

作用：

  • 用来判断“是否符合资助”。

核对重点需要重点核对：

配置列核对方式
特殊人员身份后面会匹配附件5的获得资助身份类别
实缴金额后面会匹配附件4的个人缴费金额
包含参保身份有别名时在页面新增/编辑里补充

4. 年度克隆

如果新一年配置和上一年相近，可以点击“克隆年度”。

手动操作建议：

  1. 选择来源年份。
  2. 选择目标年份。
  3. 勾选要克隆的配置类型。
  4. 如果目标年份已有旧配置且要重来，才勾选“覆盖目标年份已有配置”。

三、第二步：导入附件3全量明细

手动操作入口：参保台账 -> 参保台账明细 -> 导入 -> 导入 附件3全量明细

手动操作操作：

  1. 选择年份。
  2. 选择导入月份，例如 03月。
  3. 上传附件3 CSV。
  4. 提交后去任务中心查看是否成功。
  5. 再到“参保导入记录”查看总行数、成功行数、失败原因。

附件3会写入：

字段来源
姓名附件3姓名
身份证号码附件3身份证号码
镇（街）附件3镇（街）
村（居）附件3村（居）
纳入资助时间附件3纳入资助时间；空值用导入月份
缴费时间附件3缴费时间
医疗救助身份根据附件3身份匹配医疗救助身份配置，取最高优先级
资助参保身份根据附件3身份匹配资助参保身份配置，取最高优先级

新增、变更、取消怎么判断

情况结果
本年度从未出现过这个身份证新增
本年度已有这个身份证，医疗救助身份变了变更
之前已经取消，本月又重新出现在附件3变更
本年度已有这个身份证，本月附件3没有这个人取消
本月重复导入且身份没变保持原来的新增/变更/取消

核对重点核对重点：

  1. 列表“当前记录”应接近本年度累计台账人数。
  2. “新增/变更/取消”数量要符合本月名单变化。
  3. 抽查几个多身份人员，确认优先级最高身份是否正确。
  4. 如果身份记录里出现很多未配置身份，要回到配置里补身份或补“包含参保身份”。

四、第三步：导入附件4参保核实

手动操作入口：参保台账明细 -> 导入 -> 导入 附件4参保核实

前提：必须已经导入附件3。

附件4会写入：

字段来源
居民医保缴费金额附件4个人缴费金额
资助地或参保地（区外备注）居民/职工医保所属区划不是江津时写入

导入后会重新计算：

  • 参保类别
  • 是否参保
  • 未参保原因
  • 是否符合资助
  • 是否获得资助
  • 资助方式

核对重点核对重点：

  1. 随机查几个人，居民医保缴费金额是否与附件4一致。
  2. 区外参保人员是否出现区外备注。
  3. 如果整份文件失败，通常是年份、月份或身份证号码与附件3台账匹配不上。

五、第四步：导入附件5税务请款

手动操作入口：参保台账明细 -> 导入 -> 导入 附件5税务请款

前提：必须已经导入附件3。

附件5会写入：

字段来源
资助金额附件5代缴金额
获得资助身份类别附件5代缴类别
税务请款批次附件5请款批次
税务第一批请款请款批次包含“第一”时，写入对应代缴金额

同一个身份证在附件5有多行时，资助金额会累加。

导入后会重新计算：

字段计算规则
参保类别资助参保身份 + 居民医保缴费金额 + 资助金额，匹配资助参保身份配置
是否参保参保类别是居民一档、居民二档、大学生一档、大学生二档、需核实时为“是”
未参保原因是否参保为“是”时写“无”
是否符合资助纳入资助时间和缴费时间同月，并且身份对应明细命中时为“是”
是否获得资助符合资助且资助金额大于 0 时为“是”
资助方式获得资助为“是”时为“系统资助”，否则为“事后资助”

核对重点核对重点：

  1. 资助金额是否与税务请款明细一致。
  2. 参保类别为“需核实”的人员，要检查附件1配置金额和身份是否能匹配。
  3. 是否符合资助为“否”的人员，要重点看缴费时间、纳入资助时间、附件7身份对应明细。

六、第五步：导入附件6死亡名单

手动操作入口：参保台账明细 -> 导入 -> 导入 附件6死亡名单

前提：必须已经导入附件3。

附件6会写入：

字段来源
备注（卫健委死亡时间）附件6死亡时间

核对重点核对重点：

  1. 有死亡时间的人员，列表“死亡备注”应有值。
  2. 如果整份文件失败，通常是身份证号码没有匹配到当年台账。

七、什么时候导出哪张表

手动操作入口：参保台账明细 -> 导出

导出后到任务中心下载。

导出文件建议导出时机主要核对
资助参保对象-汇总名单导入附件1、附件2、附件3后动态身份列是否按资助参保身份记录打勾
资助参保对象-对比结果导入附件3后新增、变更、取消是否正确
特殊对象资助参保台账附件3、4、5、6都导入后金额、参保类别、是否符合资助、死亡备注是否完整

八、常见问题核对

1. 为什么有人是“需核实”

核对重点通常原因：

  1. 附件4个人缴费金额没导入或没匹配上。
  2. 附件5资助金额没导入或没匹配上。
  3. 附件1资助参保身份配置里没有对应金额组合。
  4. 身份名称不一致，需要补“包含参保身份”。

2. 为什么是否符合资助是“待核实”

核对重点通常原因：

  1. 缴费时间为空。
  2. 纳入资助时间或缴费时间格式不规范。

3. 为什么是否符合资助是“否”

核对重点通常原因：

  1. 纳入资助月份和缴费月份不是同一个月。
  2. 附件7身份对应明细没有匹配到“获得资助身份类别 + 居民医保缴费金额”。
  3. 身份别名未配置，需要补“包含参保身份”。

4. 为什么导入附件4/5/6失败

核对重点通常原因：

  1. 还没有先导入附件3。
  2. 选择的年份不对。
  3. 导入月份选择不对。
  4. 文件里的身份证号码和当前年度台账无法匹配。
  5. 文件表头不是系统模板要求的表头。

5. 为什么身份优先级是 9999

表示附件3里的身份没有匹配到当前年度配置。处理方式：

  1. 回到参保配置。
  2. 检查资助参保身份或医疗救助身份是否缺失。
  3. 如果是别名，编辑配置，补到“包含参保身份”。
  4. 重新导入附件3。

九、推荐核对流程

  1. 配置页确认附件1、附件2、附件7都有当前年份数据。
  2. 导入附件3后，看统计卡片新增、变更、取消数量。
  3. 抽查 5 到 10 个多身份人员，确认医疗救助身份和资助参保身份取最高优先级。
  4. 导入附件4后，核对居民医保缴费金额和区外备注。
  5. 导入附件5后，核对资助金额、参保类别、是否符合资助。
  6. 导入附件6后，核对死亡备注。
  7. 导出对比结果，核对新增、变更、取消。
  8. 导出特殊对象资助参保台账，核对最终字段是否完整。

十、镇街账号能做什么

镇街账号只能看和处理本镇街数据。

手动操作建议开放：

  • 参保台账明细查看
  • 参保台账明细导出本镇街数据
  • 参保台账明细有限字段编辑

手动操作不建议开放：

  • 参保配置
  • 附件3/4/5/6导入
  • 参保导入记录

镇街账号如果导出，系统会自动限制为本镇街数据。
