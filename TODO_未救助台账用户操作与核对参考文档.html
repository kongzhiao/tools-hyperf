未救助台账用户操作与核对参考文档

这份文档给业务用户使用，按步骤操作即可。所有导入文件目前只支持 .csv，系统会自动识别 UTF-8、GBK/GB18030 编码。所有导入、清洗、导出等耗时操作都走任务中心，提交后请先看任务中心结果，再回到页面核对数据。

一、先记住五个原则

  1. 先维护镇街和重大疾病编码，再按清算期导入业务数据。
  2. 附件1《未救助明细》是主数据，必须先导入附件1，附件2才有对象可匹配。
  3. 附件2《救助对象名单》只更新当月主表，不单独形成一张名单表。
  4. 清洗只做“已剔除/未剔除”标记，不删除记录。
  5. 最终数据核对以“未救助明细”和导出文件为准。

二、第一步：维护基础数据

1. 维护镇街

手动操作入口：系统管理 -> 镇街管理

作用：

  • 附件2导入时，用镇街名称或编码匹配系统镇街。
  • 管理员下放数据时，必须能匹配到镇街。
  • 镇街账号只能看到自己绑定镇街的数据。

核对重点需要重点核对：

配置项核对方式
镇街名称要和附件2里的镇街名称能对应
镇街编码如果附件2使用编码，编码必须准确
用户所属镇街镇街账号要绑定正确镇街

如果附件2导入后很多记录没有镇街，优先检查这里。

2. 维护重大疾病编码

手动操作入口：未救助台账 -> 重大疾病编码

来源：附件3《救助重大疾病编码》

作用：

  • 用于后续附件4《医疗救助应补应退排查记录》的重大疾病范围判断。
  • 普通住院不依赖重大疾病编码；门诊慢特病需要命中重大疾病编码。

核对重点需要重点核对：

配置列核对方式
病种编码与医保就诊明细中的病种编码一致
病种名称便于人工核对
状态启用的数据才参与匹配

三、第二步：选择清算期

手动操作入口：未救助台账 -> 未救助明细

手动操作操作：

  1. 选择清算期，例如 202602。

核对重点核对重点：

  1. 每次导入、清洗、下放、导出前，都先确认当前清算期。
  2. 如果列表数据和预期不一致，先检查是不是选错清算期。

四、第三步：导入附件1未救助明细

手动操作入口：未救助明细 -> 导入 -> 导入 附件1未救助明细

手动操作操作：

  1. 选择清算期。
  2. 上传附件1 CSV。
  3. 提交后去任务中心查看是否成功。
  4. 回到未救助明细页，核对统计卡片和列表。

附件1会写入：

字段来源或计算方式
序号附件1序号
姓名附件1姓名
身份证号附件1身份证号
医疗类别附件1医疗类别
医药机构名称附件1医药机构名称
入院、出院、结算时间附件1对应时间
医疗总费用附件1医疗总费用
医保政策范围费用附件1医保政策范围费用
统筹报销金额附件1统筹报销金额
大额报销附件1大额报销
大病报销附件1大病报销
进入报销金额医保政策范围费用 - 统筹报销金额 - 大额报销 - 大病报销

附件1状态怎么判断

条件状态
进入报销金额 <= 0无救助金额
0 < 进入报销金额 <= 300不通知
进入报销金额 > 300拟通知

附件1更新规则：

情况结果
同一清算期第一次出现该序号新增记录
同一清算期已存在该序号更新原记录
记录已进入已下放、已接收、已通知流程再次导入附件1不覆盖流程状态

核对重点核对重点：

  1. 当前记录数是否接近附件1行数。
  2. 抽查几条记录，进入报销金额是否按公式计算正确。
  3. 无救助金额、不通知、拟通知数量是否符合预期。
  4. 医疗类别筛选项是否出现附件1里的主要类别。

五、第四步：导入附件2救助对象名单

手动操作入口：未救助明细 -> 导入 -> 导入 附件2救助对象名单

前提：必须已经导入当前清算期附件1。

附件2会按 清算期 + 身份证号 匹配附件1主表，同一身份证可能匹配多条就医记录。

附件2会写入：

字段来源
镇街附件2镇街名称或编码匹配系统镇街
村社附件2村社
身份类别附件2身份类别
姓名附件1姓名为空或为 -- 时，用附件2姓名补齐

导入后会重新计算待处理类状态，但不会覆盖已经进入镇街流程的 已下放、已接收、已通知。

核对重点核对重点：

  1. 抽查几个身份证，确认镇街、村社、身份类别是否补齐。
  2. 没有匹配镇街的记录，要检查附件2镇街名称和镇街管理里的名称/编码。
  3. 如果整份文件失败，通常是清算期选错、附件1未导入或身份证号码匹配不上。
  4. 身份类别筛选项是否出现附件2里的主要身份。

六、第五步：配置并执行清洗

手动操作入口：未救助明细 -> 清洗规则

系统默认有一套清洗规则，管理员可以查看、编辑、保存后执行。

常见清洗规则：

规则结果
医疗类别不在保留范围内已剔除
医药机构名称命中剔除关键字已剔除
统筹报销金额 = 医保政策范围费用已剔除，备注无救助金额
大额报销 = 医保政策范围费用已剔除，备注无救助金额
大病报销 = 医保政策范围费用已剔除，备注无救助金额
普通住院救助额度已满已剔除
重特大疾病救助额度已满已剔除
大额费用住院救助额度已满已剔除
身份类别命中剔除范围已剔除

执行清洗：

  1. 确认当前清算期。
  2. 检查清洗规则是否为本次业务口径。
  3. 点击执行清洗。
  4. 二次确认后提交任务。
  5. 清洗执行中页面会展示进度，任务完成后统计会刷新。

核对重点核对重点：

  1. 已剔除数量是否符合规则预期。
  2. 抽查已剔除记录，命中规则和备注是否合理。
  3. 抽查未剔除记录，确认没有明显应剔除但未剔除的数据。
  4. 清洗规则改动后，需要重新执行清洗，旧结果才会刷新。

七、第六步：下放镇街

手动操作入口：未救助明细 -> 下放

管理员按清算期和镇街下放数据。

下放范围：

条件是否可下放
未剔除 + 拟通知 + 已匹配镇街可以下放
已剔除不下放
无救助金额、不通知不下放
未匹配镇街不能下放

下放后：

  • 记录状态变为 已下放。
  • 镇街账号可以看到本镇街已下放数据。

核对重点核对重点：

  1. 下放前先筛选 未剔除、拟通知，确认待下放数量。
  2. 按镇街抽查，确认下放镇街正确。
  3. 未匹配镇街的数据要先处理镇街匹配问题，不能直接下放。

八、第七步：镇街接收、通知和账户回填

镇街账号入口：未救助台账 -> 未救助明细

镇街账号只能看到本镇街已下放、已接收、已通知数据。

1. 接收

镇街账号进入页面后，如果当前清算期有 已下放 待接收数据，系统会提示确认接收。

接收后：

  • 状态从 已下放 变为 已接收。
  • 写入接收时间。

2. 通知与撤销通知

镇街线下通知群众后，在页面标记 已通知。

操作状态变化
标记通知已接收 -> 已通知
撤销通知已通知 -> 已接收

3. 账户回填

可对 已接收、已通知 记录回填：

  • 开户行
  • 户名
  • 银行账号

核对重点核对重点：

  1. 镇街看到的数据是否只属于本镇街。
  2. 已下放数据是否及时接收。
  3. 已通知记录是否都有线下通知依据。
  4. 导出未报销台账前，开户行、户名、账号要尽量补齐。

九、第八步：报销标记

手动操作入口：未救助明细 -> 报销标记

仅管理员操作。

用途：

  • 线下拨款或报销完成后，将记录标记为 已报销。
  • 标错时可恢复为 未报销。

核对重点核对重点：

  1. 标记前先按清算期、镇街、报销状态筛选。
  2. 标记已报销前，核对未报销台账导出文件和实际拨款名单。
  3. 不要把尚未完成拨款的数据提前标记已报销。

十、什么时候导出哪张表

手动操作入口：未救助明细 -> 导出

导出后到任务中心下载。

导出文件建议导出时机主要核对
医疗救助未救助排查明细附件1、附件2导入后，或清洗后全量排查字段、进入报销金额、清洗备注
医疗救助未报销台账清洗完成、镇街回填账户后未剔除数据、账户信息、报销状态
医疗救助未救助通知名单清洗完成、下放或通知前后未剔除数据、镇街通知名单
医疗救助应补应退排查记录重大疾病编码维护后，需要做应补应退排查时普通住院和符合重大疾病编码的门诊慢特病

导出口径：

文件当前范围
排查明细当前筛选条件下所有主表记录
未报销台账当前筛选条件下所有未剔除记录
通知名单当前筛选条件下所有未剔除记录
应补应退排查记录应补应退排查表和当前筛选条件

注意：

  1. 未匹配镇街但未剔除的数据也会导出，由人工后续处理。
  2. 未匹配镇街的数据不能下放给镇街。
  3. 导出前先确认筛选条件，尤其是清算期、镇街、剔除状态、报销状态。

十一、常见问题核对

1. 为什么导入附件1后状态是“无救助金额”

核对重点通常原因：

  1. 进入报销金额 <= 0。
  2. 统筹、大额、大病报销已经覆盖政策范围费用。
  3. 附件1金额列格式不规范，导致金额解析异常。

手动操作处理方式：

  1. 抽查医保政策范围费用、统筹报销金额、大额报销、大病报销。
  2. 用公式手算：医保政策范围费用 - 统筹报销金额 - 大额报销 - 大病报销。

2. 为什么导入附件1后状态是“不通知”

核对重点通常原因：

  1. 进入报销金额大于 0 且小于等于 300。
  2. 这类数据未达到通知阈值。

3. 为什么附件2导入后镇街为空

核对重点通常原因：

  1. 附件2镇街名称与系统镇街名称不一致。
  2. 附件2使用了镇街编码，但镇街管理里未维护编码。
  3. 附件2表头不符合模板，镇街列没有被识别。

手动操作处理方式：

  1. 回到镇街管理检查名称和编码。
  2. 抽查附件2对应行的镇街字段。
  3. 修正后重新导入附件2。

4. 为什么附件2导入后身份类别为空

核对重点通常原因：

  1. 附件2没有对应身份证。
  2. 附件2身份类别列为空。
  3. 附件2表头不符合模板。
  4. 清算期选错，导致没有匹配到当前月附件1数据。

5. 为什么清洗后数据被剔除

核对重点通常原因：

  1. 医疗类别不在保留范围。
  2. 医药机构名称命中剔除关键字。
  3. 报销金额已经达到规则中的剔除条件。
  4. 身份类别命中剔除范围。

手动操作处理方式：

  1. 查看记录的“命中规则”和“备注”。
  2. 如果规则口径不对，修改清洗规则后重新执行清洗。

6. 为什么有些数据不能下放

核对重点通常原因：

  1. 记录是已剔除。
  2. 状态不是拟通知。
  3. 没有匹配到镇街。
  4. 当前账号不是管理员。

7. 为什么镇街账号看不到数据

核对重点通常原因：

  1. 管理员还没有下放。
  2. 用户没有绑定镇街。
  3. 账号绑定镇街和记录镇街不一致。
  4. 清算期选错。

8. 为什么导出数量和页面总数不一样

核对重点通常原因：

  1. 页面当前筛选条件和导出时筛选条件不同。
  2. 未报销台账、通知名单默认只导出未剔除数据。
  3. 清算期或报销状态筛选未清空。

十二、推荐核对流程

  1. 镇街管理确认镇街名称、编码、镇街账号绑定正确。
  2. 重大疾病编码确认当前有效编码已维护。
  3. 选择清算期。
  4. 导入附件1后，核对当前记录数、进入报销金额、无救助金额、不通知、拟通知数量。
  5. 导入附件2后，核对镇街、村社、身份类别匹配情况。
  6. 执行清洗前，确认清洗规则。
  7. 执行清洗后，抽查已剔除和未剔除记录。
  8. 下放前，筛选未剔除、拟通知、已匹配镇街数据。
  9. 镇街接收后，核对已接收数量。
  10. 镇街通知并回填账户后，核对已通知和账户完整性。
  11. 导出通知名单或未报销台账，核对导出数量和关键字段。
  12. 线下拨款或报销后，管理员标记已报销。

十三、镇街账号能做什么

镇街账号只能看和处理本镇街数据。

手动操作建议开放：

  • 未救助明细查看
  • 镇街接收
  • 通知/撤销通知
  • 账户回填

手动操作视业务需要开放：

  • 本镇街数据导出

手动操作不建议开放：

  • 附件1/附件2导入
  • 重大疾病编码维护
  • 清洗规则配置和执行
  • 下放
  • 报销标记

镇街账号如果进入页面，系统会自动限制为本镇街数据。
